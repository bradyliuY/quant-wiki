# 样本外检验与滚动优化

## 概述

在训练集上「调出」的好参数，往往在真实市场上一碰就碎。样本外检验（Out-of-Sample Test）与滚动优化（Walk-Forward Optimization）就是为了回答：**这套策略对「没见过」的数据是否依然有效？** 它们是过拟合最直接的检验手段。

## 训练集与测试集

把历史数据严格切分：

| 数据集 | 用途 | 铁律 |
|--------|------|------|
| 训练集（样本内） | 确定参数 | 只能用于优化 |
| 验证集 | 调参后的二次筛选 | 最多使用一两次 |
| 测试集（样本外） | 最终检验 | **只用一次** |

切分方式：

- **时间顺序切分**（推荐）：前 70% 训练、后 30% 测试。回测必须保持时间顺序，绝不能随机打乱——随机打乱会破坏时序相关性并引入前视偏差
- **滚动前推**：更接近实盘节奏的逐步验证方式

## 样本外检验的标准流程

1. 用训练集优化参数
2. 用样本外数据运行最终参数，记录绩效
3. 对比样本内/外绩效：衰减幅度是否可接受

**衰减判读**：

- 样本外绩效与样本内接近 → 策略稳健
- 样本外绩效显著下降（如收益腰斩、回撤翻倍）→ 过拟合信号
- 样本外由盈转亏 → 策略大概率无效

## 滚动优化（Walk-Forward）

样本外检验是一次性的静态验证；滚动优化则模拟**实盘持续再优化的过程**：

```
┌──────────┬──────┬──────┬──────────┬──────┬──────┐
│  训练窗   │ 验证窗 │ ... │  训练窗   │ 验证窗 │  → 时间
└──────────┴──────┴──────┴──────────┴──────┴──────┘
   优化参数 应用参数 优化参数
```

**过程**：

1. 设定训练窗（如 6 个月）与验证窗（如 1 个月）
2. 在训练窗内优化参数
3. 将最优参数**冻结**，应用到紧随其后的验证窗
4. 记录验证窗绩效（此时参数未见过这些数据）
5. 窗口整体前移（步进一个验证窗），重复执行
6. 拼接所有验证窗绩效，得到「样本外绩效曲线」

## 滚动优化的绩效判读

将各验证窗绩效拼接后，与样本内绩效对比：

| 结果 | 结论 |
|------|------|
| 验证窗绩效与样本内基本一致 | 策略稳健，可进入实盘观察 |
| 验证窗绩效显著衰减 | 过拟合或策略逻辑随市场失效 |
| 验证窗连续亏损 | 放弃该策略族，回到逻辑层面重构 |

> 注意：滚动优化每滚动一次就用一次数据，本质上是「受控的数据窥探」。虽然比一次性优化更诚实，但仍需遵守「测试集只用一次」的纪律。

## 避免常见错误

- **训练窗太短**：参数估计噪声大，优化结果不稳定
- **优化指标单一**：只优化收益会导致参数指向高波动高风险区域，应同时约束回撤
- **参数在验证期「临时修改」**：滚动优化的前提是参数冻结，否则验证失去意义
- **忽略市场制度变化**：涨跌停规则、T+0、费率改革会改变策略前提，历史窗口未必代表未来

## 实战示例

某均线策略训练窗 6 个月、验证窗 1 个月，滚动 12 期：

- 样本内（训练窗均值）：年化 32%，最大回撤 11%
- 样本外（验证窗拼接）：年化 26%，最大回撤 14%

衰减幅度约 20%，且未由盈转亏——判定策略稳健性可接受，进入小资金实盘观察。若样本外回撤升至 30% 以上，则应回退重审策略逻辑。

## 常见误区

1. **用验证集反复调参**：验证集只用一两次，反复使用等于把它变成第二个训练集。
2. **样本外绩效好就全仓上线**：样本外仍只是历史模拟，实盘还需小资金验证（见 [回测的正确流程](/methodology/backtesting/how-to-backtest)）。
3. **窗口参数凭感觉**：训练窗长度应与策略持仓周期匹配——趋势策略需要更长训练窗。
4. **只报告最优滚动轮次**：应报告全部验证窗的拼接绩效，挑好看的单窗结果是自欺。
